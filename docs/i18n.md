# Translations

Help make GoblinFTP easier to use in your language. Translation files are in `frontend/i18n/locales/`.

English (`en.json`) is the reference. Translate the text, but keep the JSON keys and placeholders such as `{name}` unchanged.

## Improving an existing translation

Edit the file for your language, then run:

```bash
just i18n-check
```

This checks that every language has the same keys and placeholders as English. The same check runs in CI.

## Adding a new language

### 1. Create the translation file

Copy the English file and translate its values:

```bash
cp frontend/i18n/locales/en.json frontend/i18n/locales/<code>.json
```

Replace `<code>` with the language code. Use the code expected by Nuxt UI; Norwegian Bokmål, for example, uses `nb-NO`. The German file, `de.json`, is a useful example of the intended tone.

### 2. Register the language

Update these three files:

| File | Change |
|---|---|
| `frontend/nuxt.config.ts` | Add `{ code: '<code>', file: '<code>.json' }` to `i18n.locales`. |
| `frontend/app/stores/settings.ts` | Add the code to `AppLanguage` and `LANGUAGES`. |
| `frontend/app/components/Layout/LanguageSelect.vue` | Import the matching object from `@nuxt/ui/locale` and add it to `locales`, sorted by display name. |

If you need to change the display name, use the same approach as Danish: `{ ...da, name: 'Dansk' }`. If Nuxt UI has no matching language, provide a locale object for it.

### 3. Check your changes

```bash
just i18n-check
```

Open GoblinFTP, select the new language, and check that the text fits the interface.

## How the language is chosen

GoblinFTP uses the language chosen by the user first, then the `GFTP_LANGUAGE` setting, then English. It does not choose a language from the browser settings.

The backend passes the default language through to the interface. Registering the code in the three files above makes it available to users.
