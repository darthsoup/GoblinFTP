# Translations (i18n)

GoblinFTP ships 13 locales: `en`, `de`, `cs`, `da`, `es`, `fi`, `fr`, `it`, `nb-NO`, `nl`, `pt`, `sk`, `sv`. Locale files are nested JSON under `frontend/i18n/locales/`.

`en.json` is the source of truth. Every other locale file must match it on **recursive key parity** and on the **exact set of `{...}` placeholders** in each string. `frontend/scripts/i18n-check.mjs` (run via `just i18n-check`) enforces both and is gated in CI by `checks.yml`, so a mismatch fails the build.

## Improving an existing translation

Edit the file under `frontend/i18n/locales/`, keeping keys and every `{...}` placeholder identical to `en.json`, then verify:

```bash
just i18n-check
```

## Adding a new language

**1. Create the locale file.** Copy `en.json` and translate the values only, not the keys. `de.json` is the tone reference.

```bash
cp frontend/i18n/locales/en.json frontend/i18n/locales/<code>.json
```

Use the code `@nuxt/ui` expects: Norwegian Bokmål is `nb-NO`, not `no`.

**2. Register the code in exactly three places** (the codes are enumerated nowhere else):

- `frontend/nuxt.config.ts`, `i18n.locales`: add `{ code: '<code>', file: '<code>.json' }`.
- `frontend/app/stores/settings.ts`: add the code to both the `AppLanguage` union and the exported `LANGUAGES` array.
- `frontend/app/components/Layout/LanguageSelect.vue`: import the locale object from `@nuxt/ui/locale` and add it to the `locales` array (sorted by display name). If `@nuxt/ui` ships no matching object, or its native name is not the endonym you want, override it inline as Danish does: `{ ...da, name: 'Dansk' }`.

**3. Verify.**

```bash
just i18n-check   # recursive key parity plus identical placeholder sets
```

## Behavior notes

- The backend has no language allow-list. It passes the `settings.json` `language` value straight through, so the three frontend registration points are what actually gate the available set.
- Runtime selection precedence: explicit user choice (persisted to `gftp_settings` in `localStorage`), then the admin default from `settings.json`, then `en`. Browser-language detection is disabled.
